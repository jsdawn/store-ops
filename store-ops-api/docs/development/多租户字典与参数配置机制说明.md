# 多租户字典与参数配置机制说明

> 适用：RuoYi-Cloud-Plus 2.6.2（本项目 store-ops-api）
> 背景：会员域（member）管理台联调时踩了字典空值缓存 + 租户副本缺失的坑，整理成文。

## 一、机制：字典是「租户副本制」，不是全局共用

- `sys_dict_type` / `sys_dict_data` / `sys_config` **不在** `tenant.excludes` 中，走租户过滤，查询只见自己 `tenant_id` 的行。
- 框架在**开通租户那一刻**，把管理租户 `000000` 的字典和参数**复制一份**给新租户（dict_id/dict_code 由雪花重新生成）。
- 之后往 `000000` 新增的字典/参数，存量租户**不会自动获得**，必须手动同步（见第三节）。
- 平台级基础设施配置例外：`sys_oss_config`（对象存储）、`sys_client` 等在 `tenant.excludes` 中，全局共用。

### 为什么是副本制而不是共用？

框架假设每个租户都是独立运营的 SaaS 客户：

1. 租户管理员可在自己的「字典管理」页增删改，只影响本租户（如加「刷卡收款」、改 label）；
2. 租户间数据互不污染；
3. 同步时按 `dictValue` 排重——租户改过 label 的项不会被平台同步覆盖，个性化得以保留。

**业务代码不受副本制影响的保证**：凡被业务逻辑依赖的字典值（如 `biz_type='1'` 充值分支），本项目一律用常量类（`OpsMemberConstants` 等）+ char(1) 列约束 + 后端校验兜底，字典内容只负责界面展示（label、tag 颜色）。租户改字典不会破坏业务逻辑。

## 二、新功能模块带字典/参数的标准流程

1. **模块 SQL**（如 `script/sql/ops_member.sql`）只插 `000000` 的 `sys_dict_type` / `sys_dict_data`（/ `sys_config`）行；
2. 管理台「系统管理 → 租户管理」→ 点 **同步租户字典**（有新增参数再点 **同步租户参数配置**）；
3. 完事。缓存已由接口自动清理，无需手工操作。

> 对应源码：`SysTenantServiceImpl.syncTenantDict()` / `syncTenantConfig()`
> 逻辑：忽略租户过滤取 000000 全量 → 遍历所有 status=正常 的租户 → 按 dictType+dictValue 增量补缺（幂等，重复点无副作用）→ 插入后按租户 `CacheUtils.clear(CacheNames.SYS_DICT)`。

边界：同步只处理 `status=正常` 的租户；停用租户不补（不影响使用）。

## 三、踩坑实录（2026-10-12 会员域联调）

### 症状

- 充值弹窗「充值方式」radio 空白、充值流水「充值方式」列空白（`useDict('member_pay_type')` 返回空数组）。

### 根因（两层叠加）

1. **副本缺失**：`ops_member.sql` 只插了 000000 的字典行，租户 955875 开通在先，查询永远为空。
2. **空值缓存**：字典导入前页面请求过接口，空结果被 Spring Cache 缓存为 `NullValue`，之后即使补了数据接口仍返回空。

### 排查与修复过程

```bash
# 1. 确认接口返回空（token 为租户用户）
GET /system/dict/data/type/member_pay_type  →  {"code":200,"data":[]}

# 2. 查库：000000 有行、955875 没有 → 确认副本缺失
select dict_code,tenant_id,dict_label,dict_value from sys_dict_data where dict_type='member_pay_type';

# 3. 查 Redis 字典缓存结构：hash，key=<tenant_id>:sys_dict，field=dictType
redis-cli -a <密码> hkeys 955875:sys_dict
redis-cli -a <密码> hget 955875:sys_dict member_pay_type
# → ["org.redisson.spring.cache.NullValue",{}]   ← 空值缓存实锤

# 4. 修复：手工给 955875 插入副本行（dict_id/dict_code 用高位段 6101.../6102... 避开雪花），
#    再 hdel 955875:sys_dict member_pay_type 清缓存 → 接口返回 3 行
```

> 手工补副本仅适合临时救急。**正式做法永远是第二节的三步流程**（当时不知道同步接口的存在）。
> Redis 密码忘记时：`docker inspect <redis容器> --format '{{json .Config.Cmd}}'` 看 requirepass。

### 相关 Redis 缓存

| 项 | 值 |
|---|---|
| 字典缓存 | hash `"<tenant_id>:sys_dict"`，field=dictType，value=字典数据 JSON（或 NullValue） |
| 清缓存 | 接口自动清；手工清：`DEL "955875:sys_dict"`（清后下次查询回源重建） |

## 四、关联机制备忘

- **菜单权限同理**：会员菜单 3010 段插入 `sys_menu` 后，存量角色的 `sys_role_menu` 绑定不会自动出现，需在「角色管理」勾选或改库，否则接口 403（权限字符校验失败）。
- 新租户开通时：菜单（按租户套餐）+ 字典 + 参数均由框架自动初始化，无需手工处理。
